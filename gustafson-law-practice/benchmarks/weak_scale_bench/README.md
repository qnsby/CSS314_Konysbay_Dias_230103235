# Tasks 22–23: execution

From the practice root on Windows with Python 3:

```powershell
python -m pip install -r requirements.txt
python benchmarks/weak_scale_bench/run.py
python benchmarks/fit_gustafson.py
```

The benchmark runs every worker count from 1 through `os.cpu_count()`, five independent fresh Pools per configuration, in a deterministic shuffled order. Each worker task computes a float64 trigonometric reduction over k=1,750,000 elements. Arguments `--k` and `--runs` permit larger workloads and more repeats. Each repeat records an identical-work serial baseline, total parallel wall time and numerical agreement. Results and hardware metadata are exported under `benchmarks/`.

Parallel timing includes launch, dispatch, reduction, IPC and Pool shutdown. It measures application end-to-end performance; it is not a warm persistent-worker kernel benchmark. Task count equals P; Pool scheduling need not assign exactly one task to every worker. Returned PIDs are logged to expose actual task scheduling. The serial baseline excludes Pool startup by design.

Close other heavy applications and keep power settings stable when repeating. Rerunning overwrites results; regenerate the fit and update the hardware audit afterward. Mean, sample standard deviation (ddof=1), and standard error (std/sqrt(n)) are generated by the fitting script. Replicates share the same physical machine/session, so thermal drift and background activity can remain correlated.
